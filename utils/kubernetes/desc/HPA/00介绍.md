##### 目的：
HPA 的主要目标是根据工作负载自动增加或减少应用的 Pod 副本数，从而实现资源的高效利用和应用程序的高可用性。
##### 度量标准：
默认情况下，HPA 依据 CPU 利用率来做出扩展决策，但也可以配置为基于内存利用率或其他自定义指标（如请求速率）进行扩展。
##### 配置：
通过 YAML 配置文件或 kubectl 命令行工具来设置 HPA。配置包括最小/最大 Pod 副本数、目标 CPU（或内存）利用率等。
##### 工作原理：
HPA 定期（默认每分钟）从 Metrics API 获取目标 Pod 的资源使用情况。
根据当前使用率与目标使用率比较结果，决定是否需要调整 Pod 数量。
扩容或缩容操作会逐步进行，以避免对系统造成冲击。
##### 自定义指标：
Kubernetes 1.8 版本后支持自定义指标，允许用户基于 Prometheus 等监控系统提供的数据进行扩展决策。
##### API 对象：
HPA 是一个 Kubernetes API 对象，可以通过 kubectl get hpa 查看其状态，通过 kubectl describe hpa <name> 获取详细信息。
